# Tests reach internal modules only in unit tests of internal algorithms, and through one support module elsewhere

Tests drive public seams (the Streams App API through the Test Driver, the same API against real Kafka, and the State Store contract), so the engine can be refactored freely. Some internal algorithms are too intricate or too timing-dependent to pin down through those seams alone, so **unit tests may import internal modules to test internal algorithms directly**: the aborted-transaction filter (`read-committed.ts`), the Task assignor, partition ownership and its epochs, the order-preserving store-key encoding, Checkpoints, the state directory (App Process IDs and Task locks), and similar self-contained pieces such as Restore's apply loop over a Changelog reader. **Integration and crash tests must not import from `src/` directly**, except the public API (`src/index.ts`, what the package exports): whatever they need from the inside (an abort-aware reader, the on-disk layout of State Stores and Checkpoints, the store-key encoding) comes through **one test-support module, `test/support/internals.ts`**, which re-exports it with the helpers built on it. We chose this over forbidding internal imports outright, which would leave those algorithms tested only indirectly and their interleavings not at all, and over letting every test import what it likes, which would spread the engine's structure across the suites.

## Consequences

- A refactoring that moves or renames an internal module breaks its unit tests and at most `test/support/internals.ts`, never the integration or crash tests themselves. What integration tests depend on inside the engine is listed in one file.
- "No mocking of the Kafka client" still holds. The one documented exception is the ownership unit test's fake consumer-group member (`test/ownership.test.ts`): it implements only the small `GroupMember` interface `Ownership` reads (a generation, an assignment and two events), so that rebalance interleavings can be driven deterministically, which a real broker can't do. It doesn't stand in for the client anywhere else.
- Fakes of our own internal interfaces (e.g. a Changelog reader in Restore's unit tests) are not client mocks and stay allowed in unit tests.
- Internal unit tests check the algorithm's contract, not call order or private fields, like every other test.
